# Cloud 9 — Pre-event audit report (14 Nov 2026)

**Scope:** `main` @ `4aa5770` (the version running in production for CCD Kochi '26).
**Method:** six independent audits run in parallel, each on its own isolated server instance (no production systems or real Telegram API touched):

| # | Audit | What was done |
|---|---|---|
| 1 | Backend security code review | Line-by-line review of `server/src/**` (auth, HTTP, WebSocket, game engine, DB, Telegram) |
| 2 | Black-box penetration test | Anonymous, player, hall-moderator and non-admin-Telegram attacker roles against a local build + fake Telegram API |
| 3 | Frontend review | Code review of `web/src/**` + Playwright runs (small phones, dark mode, slow 3G, fonts blocked) |
| 4 | Load / soak / chaos | 3×120 realistic peak, up to 8,000 players, 15-min soak, Telegram failures, process pause, SIGKILL + restart |
| 5 | Functional smoke / E2E | Today's real run simulated: 3 halls at once, Telegram actions, rebinds, kicks, exports |
| 6 | Infra / deps / supply chain | Docker, compose, nginx, backups, `npm audit`, full git-history secret scan |

**Result:** 34 de-duplicated issues filed (#2–#35) + 1 test-flake issue (#68). **32 fix PRs opened (#36–#67), one per issue, none merged.** Production was **not** changed.

## Executive summary

- **Safe for today as deployed.** No critical findings. Load testing showed today's peak (3 rooms × 120 players) uses **<10 % of one core, 147 MB RAM, 0 errors**; the server stayed healthy up to 8,000 simulated players; no memory leaks over a 15-minute soak; recovery after a hard kill in ~1 s with scores intact.
- **High priority (fix PRs ready):** seat takeover via email rebind (#2 → #39), login hashing blocking the event loop (#3 → #42), proxy-trust/rate-limit bypass if port 3000 is ever exposed (#4 → #41), Google Fonts able to blank the page on filtered networks (#13 → #51), backups on the same disk with no tested restore (#26 → #37).
- **Mitigations already true in production today:** port 3000 is bound to 127.0.0.1 behind nginx (limits #4/#3 exposure); nginx sets `X-Forwarded-For $remote_addr`; nightly backups exist (same disk).
- **Full-history secret scan: clean.** No tokens or passwords are in git history.

## Before merging / deploying — read this

1. **Do not deploy any of this before the event ends.** Production is stable; merge and deploy afterwards, one cluster at a time.
2. **#50 (fail-closed env):** with `NODE_ENV=production` the server now refuses to start unless `MODERATORS` is set and `SESSION_SECRET` is ≥ 32 characters. Check the production `.env` first or the container will restart-loop.
3. **#45 (WebSocket Origin check):** set `ALLOWED_ORIGINS=https://cloud9.abhiramnj.com` (secondary domain) — same-host requests are allowed automatically.
4. **#53 (session revocation):** session lifetime drops from 7 days to 24 hours (moderators log in daily).
5. **#42 (login lockout):** 10 wrong passwords for one username lock it for 15 minutes; restart clears it. Consider whether you want that trade-off.
6. **#36 (emails super-only):** hall moderators no longer see participant emails or the event CSV; admin still does.
7. **#39 (email rebind):** a second device with the same email is now refused while the first is connected (`email_in_use`); switching phones still works once the old one disconnects.
8. **#55 (deps)** upgrades `@fastify/static` 8 → 10 and overlaps with **#54 (caching)** — merge #54 first, then rebase #55. `zod` stays on 3.x (patched only in v4; advisory not reachable here).
9. **#49 (container hardening)** adds `read_only`, `cap_drop: ALL`, etc. — validated with `docker compose config` only (no Docker daemon in the audit environment). Test on a staging run before production.

## Verified OK (no action needed)
- Moderator authZ matrix: owner-only vs shared routes, super access, mod WebSocket ownership; tampered/expired cookies rejected over HTTP and WS.
- XSS: payloads in every user-controlled field render escaped across all 8 page types; `javascript:`/`data:` image URLs rejected; CSV formula injection guarded in both exports.
- Privacy: no emails in public endpoints, player/projector WebSocket messages, Telegram group notifications, or logs; correct answer never sent to players/projector before reveal.
- Server-authoritative timing: deadlines, grace window, double answers, reconnect keeps score, kicked players excluded.
- Telegram: token never logged; admin-only commands; confirm buttons expire; outbox survives Telegram outages and drains afterwards.
- Lockfile and install scripts clean; git history free of secrets.
